# Handoff: 0G-4 episode log on 0G Storage

Built by a fork on Friday 6 November 2026, about 13:00 IST. Code is in `uploader/`. Evidence: `docs/evidence/0g-4.json`.

## What exists

| File | Purpose |
|---|---|
| `uploader/records.ts` | Reads a ledger's `Report` events and builds one record per report; canonical (sorted-key) JSON, so the same records always give the same bytes and root |
| `uploader/zerog.ts` | 0G Storage upload, and download with proof verification (Galileo testnet) |
| `uploader/upload.ts` | The uploader. Keeps a cursor in `.state/uploader-<ledger>.json`; the chain is the source of truth |
| `uploader/replay.ts` | Downloads a batch (or reads a local copy), rebuilds every record from the chain, compares, prints a timeline |
| `uploader/ens-hook.ts` | `publishLogRoot(device, root)`: a no-op until ENS-2. This is where `mohar.log` gets written (0G4-T6) |

Run: `node uploader/upload.ts --ledger 0x… [--rpc URL] [--device name] [--batch-size 5] [--state path] [--dry]`
and `node uploader/replay.ts --root 0x…` (or `--file path`, `--rpc URL`).

## Facts

- **SDK:** `@0gfoundation/0g-storage-ts-sdk` **1.2.12** (1.2.13 is under two weeks old), with `ethers` 6.13.1 as its peer. Installed with `--ignore-scripts`.
- **Cost:** about 0.0013 to 0.0015 0G per 2.8 KB batch. The whole phase, including one discarded upload, cost about 0.012 0G (0.0999 to 0.0877). Roughly 0.088 0G remains.
- **Uploading identical bytes twice is accepted** and returns the same root. That is what makes the crash case safe.
- **Record format** follows dev-plan.md 0G-4, plus: `ledger`, `block`, `tx`, `charged_wei`, `owed_wei`, `request_id_is_uuid` (a format check only; "dev-injected" is not a UUID), `decision.is_decision`, and the sensors word decoded per mechanism.md 7b. `device_state` equals `selected_mode` (nothing physical is switched).
- **Device name** defaults to `meter-001.mohar.eth` and is only a label until ENS-2 registers it.
- Records come from `Report` events alone, so anyone can rebuild the log from the chain.

## Surprises and limits

- The 0G SDK prints a lot of progress output on upload; the scripts don't suppress it.
- All data so far comes from tests on the local chain (injected decisions, simulated meter), so these roots are evidence the pipeline works, not a real episode log. Redo it after 0G-3 with live decisions, and point `--rpc` at the public devnet once EF-1 is funded.
- `.state/` is git-ignored. Losing it only means a re-upload of identical bytes.
- Nothing was committed or staged. Package files changed: `package.json`, `package-lock.json` (two dependencies added).
